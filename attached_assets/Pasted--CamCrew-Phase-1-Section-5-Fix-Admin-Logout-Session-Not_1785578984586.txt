# CamCrew Phase 1 — Section 5: Fix Admin Logout (Session Not Cleared)

## Objective

Fix the admin logout flow so that logging out completely destroys the authenticated Flask session before redirecting to the login page.

Currently, the frontend simply redirects to `adminlogin.html`, leaving the Flask session active. This means the browser remains authenticated and protected API endpoints can still be accessed until the session expires.

This is a security issue and must be corrected.

---

## Current Behavior

`dashboard-components.js`

```javascript
window.adminSignOut = function () {
    showToast('Signing out…', 'info');

    setTimeout(() => {
        window.location.href = 'adminlogin.html';
    }, 1200);
};
```

Problems:

* Never calls `POST /api/logout`
* Flask session remains active
* Browser cookies remain valid
* User is not actually logged out
* Protected routes remain accessible

---

## Required Behavior

When the administrator clicks **Sign Out**:

1. Show the existing "Signing out…" toast.
2. Send

```
POST /api/logout
```

with credentials included.

3. Wait for the response.
4. If logout succeeds:

   * Destroy the local authenticated state.
   * Redirect to `adminlogin.html`.
5. If the request fails because the session has already expired (401/403), still redirect to `adminlogin.html`.
6. If a network error occurs, display an error toast and do not redirect immediately.

---

## API

Use the existing endpoint.

```
POST /api/logout
```

No backend changes should be necessary if this endpoint already clears:

```python
session.clear()
```

or equivalent.

---

## Frontend Requirements

Update `dashboard-components.js`.

The logout function should become asynchronous.

Example flow:

```text
Click Logout
      │
      ▼
Show "Signing out..."
      │
      ▼
POST /api/logout
(credentials: include)
      │
      ▼
Success?
 ├── Yes → Redirect to adminlogin.html
 ├── Already logged out → Redirect anyway
 └── Network failure → Show error toast
```

The request must include:

```javascript
credentials: "include"
```

so Flask receives the session cookie.

---

## Success Conditions

After logout:

* Refreshing the browser must NOT restore the session.
* Visiting any protected API endpoint returns:

```
401 Unauthorized
```

or

```
403 Forbidden
```

depending on current backend behavior.

Opening:

```
GET /api/me
```

must return an unauthenticated response.

## Constraints

* Do not modify the logout API contract.
* Do not change authentication architecture.
* Do not replace Flask sessions with JWT.
* Preserve existing toast notifications.
* Preserve current UI styling.
* Only update the logout implementation so it correctly invalidates the server-side session before redirecting.

The goal is to ensure logout is a true server-side logout rather than only a client-side page redirect.
