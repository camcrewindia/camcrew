# CamCrew Phase 1 — Section 1: Implement Aadhaar Verification API

## Objective

Implement a backend endpoint for Aadhaar verification so that `customersignup.html` no longer receives a 404 when calling `POST /api/verify-aadhar`.

This is **not** intended to integrate with the real UIDAI system. It is a demo-safe validation endpoint that can later be replaced by a real KYC provider without changing the frontend API.

---

## Existing Context

Backend:

* Flask
* PostgreSQL (Render database)
* Server-side Flask sessions
* psycopg2
* Existing JSON API
* Existing `/api/register` and `/api/profile` endpoints

Frontend:

* `customersignup.html`
* Already performs:

```javascript
fetch("/api/verify-aadhar", {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify({
        aadhaar: aadhaarNumber
    })
});
```

This currently returns **404** because the endpoint does not exist.

---

## Requirements

Create:

```
POST /api/verify-aadhar
```

### Request

```json
{
    "aadhaar": "123412341234"
}
```

---

## Validation Rules

Reject the request if:

* Aadhaar is missing
* Not a string
* Contains non-numeric characters
* Length is not exactly 12 digits

Return:

```json
{
    "error": "Invalid Aadhaar number."
}
```

with HTTP **400**.

---

## Demo Verification Logic

For this phase, no external API should be called.

If validation succeeds:

Return HTTP **200**

```json
{
    "verified": true,
    "name": "Demo User",
    "message": "Aadhaar verified successfully."
}
```

---

## Error Handling

Return JSON for every response.

Examples:

400

```json
{
    "error": "Invalid Aadhaar number."
}
```

500

```json
{
    "error": "Unable to verify Aadhaar."
}
```

Never return HTML error pages.

---

## Code Quality

Follow the existing coding style of `app.py`.

Use:

* Flask request handling
* `jsonify()`
* Existing error response conventions
* Existing logging style if present

Do **not** introduce new frameworks.

---

## Future Compatibility

Structure the verification logic so it can later be replaced with:

```python
verify_aadhaar_with_provider(aadhaar)
```

without changing the route or frontend.

Keep all provider-specific logic isolated.

---

## Frontend Compatibility

The endpoint must be compatible with the existing frontend.

No frontend changes should be required.

---

## Acceptance Criteria

* `/api/verify-aadhar` exists.
* Invalid Aadhaar numbers return HTTP 400.
* Valid 12-digit numeric Aadhaar returns HTTP 200.
* No frontend modifications are required.
* `customersignup.html` no longer receives a 404.
* Responses are always JSON.
* Code is clean, readable, and ready for future integration with a real KYC service.
