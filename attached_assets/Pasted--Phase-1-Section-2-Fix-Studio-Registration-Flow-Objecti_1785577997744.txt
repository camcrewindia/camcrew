# Phase 1 – Section 2: Fix Studio Registration Flow

## Objective

Replace the current broken studio registration flow with a secure, recoverable account creation process.

The current implementation creates studio accounts using `crypto.randomUUID()` as the password. Because this password is never shown or stored anywhere the user can access, every newly created studio account becomes permanently inaccessible after registration.

This implementation must completely remove that behavior.

---

## Current Flow (Broken)

```
Studio Signup

↓

Collect business information

↓

Generate random password

↓

POST /api/register

↓

Redirect

↓

User can never log in again
```

Problems:

* Remove every usage of `crypto.randomUUID()` for passwords.
* Never generate passwords automatically.
* Never create accounts without the user choosing a password.

---

## Required New Flow

Implement the following registration sequence:

```
Stage 1
Business Details

↓

Stage 2
Email Verification (existing or future OTP)

↓

Stage 3
Create Password

↓

POST /api/register

↓

Automatically log in

↓

Redirect to Studio Dashboard
```

The account should only be created after all required information has been collected.

---

## Frontend Requirements

### Stage 1

Collect:

* Business Name
* Owner Name
* Email
* Phone
* Business Address
* GST (optional if applicable)

Do not register the account yet.

Temporarily store this data in JavaScript state until registration is complete.

---

### Stage 2

Use the existing verification step.

If OTP has not yet been implemented, preserve the current UI but structure the code so that it can later call:

```
POST /api/send-otp
POST /api/verify-otp
```

Do not register the user before verification succeeds.

---

### Stage 3

Add a password creation screen.

Required fields:

* Password
* Confirm Password

Validation:

* Minimum 8 characters
* Maximum 128 characters
* Passwords must match
* Display clear validation messages

Do not allow submission unless validation passes.

---

## Registration Request

When Stage 3 completes successfully, submit a single registration request.

Example:

```json
{
  "email": "studio@example.com",
  "password": "StrongPassword123!",
  "role": "studio",
  "display_name": "ABC Studio"
}
```

The frontend must never generate passwords.

---

## Backend Requirements

Reuse the existing:

```
POST /api/register
```

No API changes should be required.

The backend should:

* Hash the password using Werkzeug.
* Store the new user.
* Create the session.
* Return the existing success response.

No random password generation should exist anywhere in the backend.

---

## Automatic Login

After successful registration:

1. The user should already have an active Flask session.
2. Calling:

```
GET /api/me
```

must return:

```json
{
  "authenticated": true,
  "role": "studio"
}
```

---

## Redirect Logic

Replace the current redirect.

Instead of:

```
studiosignup.html
```

redirect to the appropriate destination, for example:

```
studio-dashboard.html
```

or

```
professionalsetup.html
```

depending on the intended onboarding flow.

A registered studio user must never be redirected back to the signup page.

---

## Remove

Delete all code related to:

* `crypto.randomUUID()` passwords
* Hidden/random passwords
* Automatic password generation

Passwords must always come directly from user input.

---

## Acceptance Criteria

The implementation is complete when:

* No random passwords are generated.
* Every studio chooses their own password.
* Password confirmation is enforced.
* Registration occurs only after all stages complete.
* The user is immediately logged in after registration.
* The user can log out and log back in using their chosen password.
* Studio users are redirected to the correct dashboard instead of the signup page.
* Existing customer and professional registration flows remain unaffected.

Maintain the existing visual design, Tailwind styling, animations, and multi-step UX while replacing only the registration logic.
