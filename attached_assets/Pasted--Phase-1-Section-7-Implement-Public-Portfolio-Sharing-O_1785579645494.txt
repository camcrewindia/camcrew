# Phase 1 – Section 7: Implement Public Portfolio Sharing

## Objective

Implement the missing `/shared/<share_id>` feature so that every share link generated by `professional-profile.html` opens a publicly accessible portfolio page instead of returning a 404.

The implementation must integrate cleanly with the existing Flask + PostgreSQL backend and preserve the current frontend architecture.

---

## Current Situation

`professional-profile.html` generates links in the following format:

```
https://<domain>/shared/<share_id>
```

However:

* No `/shared/<share_id>` route exists.
* Every generated link returns **404 Not Found**.
* Portfolio sharing is therefore completely non-functional.

---

## Goals

Implement an end-to-end public portfolio sharing system.

Requirements:

* Public access (no login required).
* Read-only.
* Works for both images and videos.
* Uses existing authentication/session system without modification.
* Compatible with PostgreSQL.
* Does not break existing professional dashboard functionality.

---

## Database

If a portfolio table already exists:

* Extend it with any missing fields.

Otherwise create a table similar to:

```sql
portfolio_items
---------------
id SERIAL PRIMARY KEY
professional_id INTEGER NOT NULL
title TEXT
description TEXT
file_url TEXT
file_type TEXT
share_id TEXT UNIQUE
is_public BOOLEAN DEFAULT TRUE
created_at TIMESTAMP DEFAULT NOW()
```

Requirements:

* `share_id` must be unique.
* Existing uploads should receive generated share IDs if missing.
* `share_id` should be URL-safe.

Example:

```
3f9d8ab712ce
```

Avoid sequential IDs.

---

## Backend

Implement:

```
GET /shared/<share_id>
```

Workflow:

1. Look up portfolio item using `share_id`.
2. Return 404 if not found.
3. Return 404 if marked private.
4. Load professional information.
5. Render a public portfolio page.

No authentication required.

---

## Public Portfolio Page

Create a new page:

```
shared.html
```

or render dynamically through Flask.

The page should display:

* Professional name
* Portfolio title
* Description
* Image or video preview
* Upload date (optional)
* Contact button
* CamCrew branding

Do **not** expose:

* Email
* Internal user ID
* Payment information
* Dashboard controls
* Edit/Delete buttons

This page is read-only.

---

## Media Support

If:

```
file_type == image
```

Display:

```
<img>
```

If:

```
file_type == video
```

Display:

```
<video controls>
```

Gracefully handle unsupported formats.

---

## Professional Dashboard

Keep the existing Share button.

When clicked:

* Generate a share URL.
* Copy it to clipboard.
* Display:

```
Share link copied!
```

If a share ID does not yet exist:

* Generate one.
* Save it.
* Return the URL.

---

## API

If necessary, implement:

```
POST /api/portfolio/<id>/share
```

Behavior:

* Create a share ID if one does not exist.
* Return:

```json
{
  "shareId": "3f9d8ab712ce",
  "url": "https://example.com/shared/3f9d8ab712ce"
}
```

If a share ID already exists:

Return the existing one instead of generating another.

---

## Security

Requirements:

* No authentication required to view shared pages.
* Only public portfolio items are accessible.
* Validate `share_id`.
* Prevent SQL injection through parameterized queries.
* Return proper HTTP status codes.
* Do not expose internal database identifiers.

---

## Error Handling

404

```
Portfolio not found.
```

Private

```
This portfolio is no longer publicly available.
```

Invalid ID

```
Invalid share link.
```

---

## UI Requirements

Match the existing CamCrew design:

* Tailwind CSS
* Shared header/footer where appropriate
* Responsive layout
* Glassmorphism styling
* Dark mode support
* Professional presentation

---

## Acceptance Criteria

✓ Existing Share buttons produce working URLs.

✓ Visiting `/shared/<share_id>` displays the public portfolio.

✓ Images render correctly.

✓ Videos play correctly.

✓ Private items cannot be accessed.

✓ Invalid links return 404.

✓ No login is required.

✓ Compatible with the PostgreSQL migration.

✓ Existing dashboard functionality remains unchanged.

The implementation should be production-ready, cleanly integrated into the current Flask application, and follow the project's existing coding style and architecture.
