# CamCrew Phase 1 – Section 6: Connect the Order Tracking UI

## Objective

The backend already exposes:

```
GET /api/customer/orders/<order_id>/track
```

This endpoint is implemented and working, but the frontend never calls it. The goal is to integrate it into the customer dashboard so users can view detailed tracking information for each order.

---

## Requirements

### 1. Locate the customer orders UI

Find where `customer-profile.html` renders the customer's order history.

Each order card/row should gain a **Track Order** button (or use the existing one if present).

---

### 2. Fetch tracking information

When the user clicks **Track Order**:

```
GET /api/customer/orders/<order_id>/track
```

Use:

```javascript
fetch(`/api/customer/orders/${orderId}/track`, {
    credentials: "include"
});
```

Handle:

* 200 OK
* 401 Unauthorized
* 404 Order not found
* Network errors

Do not reload the page.

---

### 3. Display a tracking modal

Create a responsive modal using the existing Tailwind styling.

Show:

* Order ID
* Current Status
* Tracking Number (if available)
* Courier (if available)

Then render the tracking timeline.

Example:

```
● Order Placed
  Jul 12, 2026 09:41

● Payment Confirmed
  Jul 12, 2026 09:42

● Packed

● Shipped

● Out for Delivery

○ Delivered
```

Completed stages should be visually distinct from pending stages.

---

### 4. Loading state

While waiting for the API:

* Disable the Track button
* Show a spinner
* Prevent duplicate requests

---

### 5. Empty state

If no tracking events exist, display:

> Tracking information is not yet available.

instead of leaving the modal blank.

---

### 6. Error handling

Show user-friendly messages:

401

```
Please sign in again.
```

404

```
Tracking information could not be found.
```

Network failure

```
Unable to load tracking information.
Please try again.
```

---

### 7. Reuse existing styles

Do not introduce a new design system.

Reuse:

* Existing Tailwind utilities
* Existing glassmorphism cards
* Existing modal styles (if available)
* Existing button components
* Existing toast/notification system

Maintain visual consistency with the rest of the customer dashboard.

---

### 8. Accessibility

The modal should:

* Close with Escape
* Close when clicking outside
* Trap keyboard focus while open
* Restore focus to the Track button after closing

---

### 9. Keep the backend unchanged

The existing Flask endpoint is already implemented.

Do not modify:

* app.py
* database schema
* PostgreSQL queries

Only integrate the frontend with the existing API.

---

## Deliverables

* Working Track Order button
* API integration
* Responsive tracking modal
* Timeline UI
* Loading, empty, and error states
* Clean, maintainable JavaScript
* No regressions to the existing customer dashboard
